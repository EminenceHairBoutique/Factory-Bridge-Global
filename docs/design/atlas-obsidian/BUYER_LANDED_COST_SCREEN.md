## 1. What the screen is for

The comparison screen groups quotations by trade term and shows landed-cost lines inline. This screen is where the buyer works the inputs: which FX rate applies on a date, which freight estimate and which duty assumption to use, what each quotation would cost delivered line by line, and which of those results is worth keeping as an immutable snapshot. A total exists only when nothing required is missing; quotations on different trade terms are ranked against each other only then.

## 2. Layout

- **Header**: title, lead, chips (project, brief quantity, today), "Open comparison", "New scenario".
- **Snapshots** (left, 17 rem at `xl`): "New scenario" row, then saved snapshots newest first with a complete/partial count and a "Ranked" chip when the cross-term ranking existed; name, as-of date and saved time.
- **Saved snapshot panel**: quantity, as-of, the FX line ("USD @ 7.2000 CNY per USD (source, date; 1 day before as-of)"), FX rows cited, freight estimate, duty assumption, generated by and when, engine version and inputs hash. "New scenario from these inputs" copies the inputs with today's date; "Reports" links to the reports screen for that quantity. The panel states that the snapshot is immutable.
- **New scenario panel**: quantity (5,000 / 10,000 / 25,000), as-of date with the resolved FX as its hint, freight estimate select (provider or manual, mode, status, valid-until; the estimate's note as hint), duty assumption select (heading, rate, basis, reviewer; the assumption's note and who recorded it as hint). Errors block "Save snapshot"; warnings show above it.
- **Ranking notice**: "Lowest estimated landed cost (all inputs present)" with the ordered suppliers and totals, or "Cross-term ranking unavailable" naming the suppliers whose required lines are missing.
- **Landed-cost lines**: at `md`+ a table with one column per eligible quotation (trade term and currency under the name), one row per line type, each cell showing the USD amount (the CNY original under the goods line), the status chip (`StatusChip`) and the source on hover; the footer row shows "Estimated landed total" with an "n estimated" or "All sourced" chip, or "Partial — excludes: …", or "No USD total — goods could not be converted (missing_fx)". Below `md`, one card per quotation with the same lines.
- **Why each quotation stands where it does**: per quotation, Complete / Partial / Not ranked, "Eligible for ranking", and the explanation sentences (exclusion reason, validity unconfirmed, missing FX, each missing or estimated line).
- **Right rail**: how a line gets its status, the FX rule, the duty rule, immutability, the session log.

## 3. Rules mirrored (display only; the engine lives in `packages/domain`)

| Rule | Where | Behaviour shown |
| --- | --- | --- |
| FX lookup | `fxRateFor` = `app.fx_rate_for` | the rate dated as-of, else the latest earlier within 3 days, else `missing_fx`; CNY quotations then have no USD goods line and no total; the rate row id is cited on the snapshot |
| Freight status | `freightLines` | mirrors the estimate: `sourced` only when the estimate is sourced **and** a document is attached; otherwise `estimated`; an estimate expired at the as-of date cannot be used for a new scenario (but a saved snapshot that used it while valid keeps it, unchanged) |
| Duties | `dutyLine` | goods × rate only from a person-recorded assumption with a rate (an `unverified` assumption has none, so the line stays missing); MPF and HMF added when the assumption says they apply; the source names the basis and the reviewing broker |
| Complete | `evaluateQuote` (shared with the comparison) | no required line missing; required lines depend on the trade term; lines the term includes are `n/a` and never summed |
| Partial | `partialText` | never a number; "Partial — excludes: …" from the missing lines |
| Ranking | `buildScenario` | only when at least two quotations are eligible and every eligible total is complete; label "Lowest estimated landed cost (all inputs present)" |
| Snapshot | `snapshotFrom` | inputs, exact FX row ids, a display hash of the inputs, engine version, who and when; immutable |

The shared comparison helper gained an optional FX-rate argument (`toUsd`, `evaluateQuote`, `compareQuotes`), defaulting to the demo reference rate so the comparison and the reports are unchanged; `null` means no usable rate and flags `missing_fx`.
